Traces to training data: the scenario system, explained

This branch turns ~1,000 recorded agent conversations into validated training scenarios, trains an agent on its own judged successes inside a simulated environment, and measures the result against a baseline built to be un-foolable. Training through it lifts a 9B agent 6–7 points over base. This page explains how each piece works, in enough detail to rebuild it.

Two colors are used consistently everywhere below: DATA — making scenarios and training episodes MEASUREMENT — evaluating models fairly

1 · The problem this solves

In one line: real agent traces are abundant but unusable as-is — this system converts them into scenarios a machine can grade, and everything else follows from that.

The raw material is OpenTelemetry traces of customer-service agents using tools. Raw traces can't train a new agent well (one fixed path per task) and can't evaluate one at all (no success criterion). The system converts traces into scenarios — a task, a seed environment state, and a checklist a judge can grade — then uses them twice: on the data side to manufacture training episodes, and on the measurement side to score models reproducibly.

2 · The big picture

In one line: five stages — mine, synthesize+validate, self-collect, fine-tune, evaluate — with the simulator and the checklist judge appearing at every stage after the first.

Mine DATA wmh/scenarios · facets → cluster → select
Each trace becomes an embeddable "facet" (task summary + tool signature + domain + outcome); facets are clustered and a 60-scenario pool is drawn. Train and eval traces are hash-split first, so pools can never share a source.
chosen source traces
Synthesize + validate DATA build_scenario_set(..., judge_provider=opus)
gpt-5.4 writes each scenario from its source trace. An Opus 4.8 judge back-checks the checklist against that trace; a failure regenerates once, then drops. An invalid scenario cannot exist downstream.
validated scenario pool
Self-collect DATA collect_bc.py — "filtered behavior cloning"
The base student (Qwen3.5-9B) attempts each scenario 6× inside the simulated environment (a "world model": gpt-5.4 playing the tools). The judge grades each attempt; at most 2 passing episodes per scenario survive. No teacher, no hints.
training episodes (JSONL chat messages)
Fine-tune DATA train_sft_box.py · LoRA on an H100
Episodes explode into per-turn samples; loss lands only on the model's own turns. ~25 minutes per adapter.
adapter
Evaluate MEASUREMENT eval_student.py --eval-pool eval_pool_v2.json --passes 3
Every model runs the same frozen 74-scenario held-out pool, 3 passes each, same simulator and judge, against a 3-seed random baseline under a decision rule fixed in advance.

3 · The one trick: the checklist is the universal contract

In one line: one data-format decision — every scenario carries a machine-gradable checklist — lets a single judge power validation, training-data filtering, and evaluation, so improvements to any of them compound.

Scenario = task + seed state + checklist
the checklist is a list of externally checkable outcome statements
judge.score(task, checklist, episode_steps) → pass_rate, success
at build timeValidity gate
Judge checks the checklist against the source trace; disagreement kills the scenario.
at collection timeTraining filter
Only episodes passing every item become training data — no human in the loop.
at eval timeThe metric
Success = all items pass; pass-rate = fraction passed. Same judge, every arm.

4 · Implementation details

In one line: the exact mechanisms — embedding text, selection parameters, the collection loop's budgets and keep rule, the LoRA recipe, and the decision rule — as shipped.

4.1 The facet and what gets embedded

Clustering operates on a per-trace summary. The embedded text deliberately carries the capability, not just the phrasing — this single change lifted mined selection from −8 points to parity (§9):

# wmh/scenarios/facets.py (shipped, trimmed)
class TraceFacet(BaseModel):
    task_summary: str      # <=30 words, extracted by a cheap LLM from a trace digest
    tool_signature: str    # "find_user>get_order>exchange_items" — computed in code
    domain: str | None     # from trace metadata, computed in code
    outcome: Outcome       # success / failure / unknown

    def embed_text(self) -> str:
        # "[retail] Exchange a delivered laptop | tools: find_user>get_order>exchange_items"
        parts = [f"[{self.domain}]"] if self.domain else []
        parts.append(self.task_summary)
        text = " ".join(parts)
        return f"{text} | tools: {self.tool_signature}" if self.tool_signature else text

4.2 Selection parameters

  • SemDeDup at cosine ≥ 0.95 within each cluster (thirty rewordings can't claim thirty slots).
  • Hybrid allocation: 70% of budget proportional to cluster mass, 30% round-robin for tail coverage; medoid first, then farthest-first within a cluster; every failure category keeps ≥1 exemplar.
  • Budgets: 60 scenarios per training pool; 95 → 74 valid for the eval pool.

4.3 The collection loop

# collect_bc.py — the numbers that matter
samples per scenario   6      (temperature 1.0)
keep per scenario      ≤ 2    passing episodes, ranked by (pass_rate desc, fewer turns)
student max_tokens     10240  # reasoning eats budget; lower values yield 0-step episodes
judge max_tokens       8192   # reasoning judges truncate verdicts mid-JSON below this
max episode steps      10
world model            frozen()   # rollouts never enter its retrieval index
final message          appended as a judged step  # "inform the customer" items live there

Kept episodes keep the student's private reasoning (<think>…</think> on each assistant turn). The student must be served with vLLM's --reasoning-parser qwen3, which routes reasoning to a separate field — the collection code depends on that separation for clean targets.

4.4 The training recipe

# train_sft_box.py — identical for every arm
LoRA        r=32, alpha=64, dropout=0.05, all attention+MLP projections
optimizer   lr=1e-4 cosine, warmup 3%, 3 epochs, effective batch 8
loss        completion-only; prompt = chat history with PRIOR think-blocks stripped
            (matches what the model sees at inference); target keeps its think-block
precision   bf16, gradient checkpointing, max_length 8192, save_strategy="no"
scale       ~60–75 episodes → 200–320 per-turn samples → ~25 min on one H100

4.5 The measurement apparatus

  • Frozen eval pool: 74 validated scenarios from the hash-disjoint eval split (59 telecom / 9 airline / 6 retail), committed at 4adc4b5, immutable.
  • Multi-seed baseline: the random comparator is three independently drawn, fully trained arms — 45.0 / 51.8 / 45.5 → 47.4% ± 3.8 success. Single draws are never baselines: on a smaller earlier pool, single-seed rankings inverted entirely when the pool grew, which is why this apparatus exists.
  • Pre-registered decision rule: "beats random" requires a paired per-scenario delta > 2× the seed spread (7.6 pts) with sign-test p<0.05. Every number is a mean of 3 passes; budgets (scenarios, rollouts, training samples) are matched across arms.

6 · What training through the system buys

The training loop is the proven asset: ~+6 points from 60 scenarios and 360 self-rollouts, no teacher and no human labels. Mined and random selection perform equivalently (paired 33W/27L/14T — inside noise); the selection question is open work (§10).

7 · How the design protects its own numbers

In one line: the components most able to silently corrupt results — the judge, the serving stack, and the simulator — each carry a structural guard.

  • The judge sees everything it grades: the final user-facing message is appended as a judged step, and the verdict budget is 8K tokens (below that, truncated verdicts read as silent failures). Enforced in code with a regression test.
  • Reasoning separation is load-bearing: without the serving-side reasoning parser, think-text leaks into training targets in a way no downstream metric flags; a smoke generation checks the separation before any collection.
  • The simulator can't learn from the experiment (world_model.frozen()), train/eval traces are hash-disjoint by construction, and baselines can't be cherry-picked — frozen pool in git, 3-seed mean, decision rule that predates every arm it judges.

10 · Limitations & future work

In one line: the open problems are the selection question, the simulator boundary, and the single judge — and the next arm (skill-based generation) is chartered with its main design obstacle identified.

Limitations

  • Selection doesn't yet earn its complexity: mined selection performs exactly as well as random.shuffle. The pipeline's proven value is scenario construction, not training-data selection.
  • Everything lives inside the world model; claims here are claims about simulated performance. Effects under ~7.6 points are undetectable by design — the decision rule trades sensitivity for trustworthiness.
  • The judge is a single point of epistemic failure: one model family grades validation, filtering, and eval; a judge blind spot would be invisible to every metric.
  • Collection wastes budget at the extremes: never-passed scenarios contribute nothing (13–28 of 60 slots per draw); always-passed ones contribute redundancy.

Future work (chartered, in priority order)

  • Skill-extraction generation (next arm): synthesize novel scenarios from a skill inventory instead of replaying traces — the one approach with a teacher-controlled, budget-matched win over random selection in the literature (Instruct-SkillMix). Blocking design problem: generated scenarios have no source trace for the validity gate; planned replacement is skill-spec agreement + a simulator solvability probe + embedding dedup against the frozen eval pool to prevent eval leakage.
  • Difficulty-aware budget reallocation: shift rollouts toward the ~12.5–87.5% pass-rate band (DART-Math / HS-STaR); expected +1–2 pts, so it rides along rather than leads.
  • Failure-contrast training: passing/failing pairs on the same scenario are preference-learning signal at zero extra collection cost (4 of 6 rollouts are currently discarded).
